2. **全网搜索** 该公司的历史资料（使用 WebSearch + smart-web-fetch）

## 输出结构模板

报告的HTML结构必须严格遵循以下模板：

### 一、顶部
- 公司名称 + "发展史·像小说一样叙事"
- 副标题："管理层言行与企业文化篇"
- 银月tag + 日期

### 二、企业文化概括框
- 用"一句话/一个词"概括企业文化（加高亮标签）
- 一段100-200字的展开说明

### 三、编年史正文

把发展历程分为3-7个"时代"（era），每个时代包含若干年份。

**每个年份固定格式：**
- 【年份标签】+【主标题】
- 正文部分：还原背景、人物、事件、当时的**环境约束**（必须写清楚"发生了什么"再分析"意味着什么"）
- 若有管理层名言，用引用块呈现（`<blockquote>`），标注时间、场合、人物
- 【洞察卡片】用有色左边框区分性质：
  - ✅ **绿色边框** = 说到做到、文化正面践行
  - ⚠️ **黄色边框** = 有争议、需要多角度看待
  - 🚩 **红色边框** = 言行明显不一致、重大问题、文化背离

### 四、结语评分区（深色背景）
- 一段总结性文字：企业文化概括 + 言行一致性整体评价
- 评分板块：百分制，逐项列出加分项和扣分项及理由
- 总体评级：正面 / 中性偏正面 / 中性 / 中性偏负面 / 负面

### 五、名言摘录
- 管理层经典语录汇总，每条标注时间、场合、人物

### 六、页脚
- 作者、数据来源声明、报告日期

## 深度分析框架

分析时必须执行以下10条逻辑约束：

### 1️⃣ 还原具体场景
每个关键决策/事件，必须先写清楚"当时发生了什么、对手做了什么、环境约束是什么"，再下判断。不能只看结果不看背景。

### 2️⃣ 多视角呈现
对于有争议的事件（如商业战争、监管处罚、产品失败），至少从以下角度分析：
- **公司自身**视角
- **竞争对手**视角
- **用户/社会**视角
- **制度环境**视角
最后给出**综合判断**，避免单一叙事。

### 3️⃣ 区分性质
**商业竞争**（进入新市场、模仿产品）和**法律/道德问题**（窃取数据、不正当手段）要明确区分，不能用同一把尺子衡量。

### 4️⃣ 可能性分析
对重大决策，必须分析"当时还有其他选项吗？如果有，为什么没选？如果没有，约束是什么？"。这比简单说"做错了"更有价值。

### 5️⃣ 制度归因
某些商业行为的问题可能不是"企业道德"的问题，而是"制度缺位"的问题。要把企业责任和制度环境分开讨论，避免把所有问题都归到"企业文化不行"。

### 6️⃣ 信息来源
关键数据、事件描述、管理层名言必须标注可信来源（财报、新闻报道、会议记录等）。避免使用百科类二手源作为唯一信源。

### 7️⃣ 自我质疑机制（关键补丁）
**这是最重要的补充规则。** 当遇到有争议的重大事件时，你不能只从一个方向分析下结论。在写出最终判断之前，必须先自问自答以下3个问题：

**Q1：反对我现在这个结论的最有力的3个理由是什么？**
- 例：如果你认为"公司霸道"，就要问——对手当时做了什么？是不是违法在先？公司有合法维权手段可用吗？
- 例：如果你认为"公司是被迫的"，就要问——它有没有更温和的选项？它自己是不是先挑事的一方？

**Q2：如果我是这家公司的CEO，面对当时的情况，我能做得更好吗？**
- 真的存在一个"既不牺牲用户利益、又能保住核心资产"的完美方案吗？
- 如果这个方案不存在，那评判时就应当考虑"无解困境"因子

**Q3：这件事的根源，多少是公司自身的问题，多少是制度/法律的不完善？**
- 不能用"企业文化不行"解释一切。要把企业责任和外部环境约束区分开

> 这三问是**内部思考过程**，不在报告中展示自问自答的原始步骤。你辩完后，把最终的条理化结论写成洞察卡片即可。读者看到的是经过梳理的分析，不是草稿。

### 8️⃣ 言行一致性
重点关注管理层说的话有没有实现。判断时区分：
- 真心想做成但没做成 → **能力问题**
- 说了但根本没认真做 → **态度问题**
- 说了然后做到了 → **信用加分**
- 嘴上说一套实际做另一套 → **重大减分**

### 9️⃣ 压力测试
重点关注行业困难时期、舆论危机时期的管理层言行。在"公司利益受损"和"兑现价值观"冲突时，管理层选了哪边？这种时候最看人品。

### 🔟 外部校准
对报告中的核心结论，搜索对照第三方权威来源（媒体深度报道、学术研究、分析师报告）进行校准，避免单一信源偏差。
