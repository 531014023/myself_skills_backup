## 执行规则（最重要）

**此Skill激活后，严格按以下流程执行：**

1. **首先读取本skill下的 references/analysis-framework.md**，加载深度分析框架
2. **全网搜索** 该公司的历史资料（使用 WebSearch + smart-web-fetch）
3. **🔴 必做：执行一票否决专项搜索** — 按 framework.md 的1.5节要求，专门搜索D/E/F类行为（消费者欺诈、结构性失信、系统性违法）。**在编年史开始之前先确认该企业是否有一票否决问题，这决定了后续报告的结构（评分还是取消评分资格）。**
4. **按框架要求** 梳理编年史、标注言行一致性、分析困难时期表现
5. **输出自包含HTML报告**（含完整样式，结构严格按模板）
    - 如果没有触发一票否决 → 使用带评分板块的完整模板
    - 如果触发了一票否决 → 评分板块改为"取消评分资格"格式

报告保存到用户工作区，文件命名格式：`{公司名称}_发展史_{YYYY-MM-DD}.html`

## 输出结构模板

报告的HTML结构必须严格遵循以下模板：

### 一、顶部
- 公司名称 + "发展史"
- 副标题："企业历史与企业文化"
- 作者tag（使用本skill的agent名称或实际作者名）+ 日期

### 二、企业文化概括框
- 用"一句话/一个词"概括企业文化（加高亮标签）
- 一段100-200字的展开说明

### 三、编年史正文

把发展历程分为3-7个"时代"（era），每个时代包含若干年份。

**每个年份固定格式：**
- 【年份标签】+【主标题】
- 正文部分：还原背景、人物、事件、当时的**环境约束**（必须写清楚"发生了什么"再分析"意味着什么"）。正文以客观陈述为主，不大量分析，所有判断进洞察卡片和评分板块。
- 若有管理层名言，用引用块呈现（`<blockquote>`），标注时间、场合、人物
- 【洞察卡片】用有色左边框区分性质：
  - ✅ **绿色边框** = 说到做到、文化正面践行
  - ⚠️ **黄色边框** = 有争议、需要多角度看待
  - 🚩 **红色边框** = 言行明显不一致、重大问题、文化背离
  正文末尾可选加：
  - 【维度标签】值：本分 | 用户导向 | 言行一致 | 危机品格 | 进化力
  - 【关键词标签】自由标注，如"说到做到、自我颠覆、进化"
  示例：✅ 本分 | 2012年方洪波改革 → 判断正文 → 关键词：说到做到、进化

### 四、结语评分区（深色背景）
- 一段总结性文字：企业文化概括 + 言行一致性整体评价
- 评分板块：百分制，按5个品格维度评分，每个维度逐项列出加分项和扣分项及理由，同时标注趋势箭头（↑/→/↓）

  **评分理由格式：详见 framework.md 5.4节（起始分80 + 加减当量表 + 🚫双重约束 + ⭐高线规则）**

  > 以下示例仅为格式参考，具体当量以5.4节最新规则为准：
  > ```
  > ➖ 基础(重) -8 — 品控问题频发，消费者投诉居高不下
  > ➕ 基础(重) +8 — 给Labubu主动降温，保护IP生命周期
  > ⭐ 高线(中) +10 — 王宁在业绩巅峰期自曝组织只打70分
  > 🚫 底线(主动) -10 + 上限70 — 承诺"绝不裁员"与实际缩编的落差
  > ```

- 综合评分下方增加整体趋势说明：↑ 品格在上升 / → 基本持平 / ↓ 品格在退化
- 总体评级：正面 / 中性偏正面 / 中性 / 中性偏负面 / 负面

### 评分维度

详见 framework.md 5.4节：本分 / 用户导向 / 言行一致 / 危机品格 / 进化力（各100分制，综合取简单平均）

### 五、名言摘录
- 管理层经典语录汇总，每条标注时间、场合、人物

### 六、页脚
- 作者、数据来源声明、报告日期

## 深度分析框架

分析时必须执行以下10条逻辑约束：

### 1️⃣ 还原具体场景
每个关键决策/事件，必须先写清楚"当时发生了什么、对手做了什么、环境约束是什么"，再下判断。不能只看结果不看背景。

### 2️⃣ 多视角呈现
对于有争议的事件（如商业战争、监管处罚、产品失败），至少从以下角度分析：
- **公司自身**视角
- **竞争对手**视角
- **用户/社会**视角
- **制度环境**视角
最后给出**综合判断**，避免单一叙事。

### 3️⃣ 区分性质
**商业竞争**（进入新市场、模仿产品）和**法律/道德问题**（窃取数据、不正当手段）要明确区分，不能用同一把尺子衡量。

### 4️⃣ 可能性分析
对重大决策，必须分析"当时还有其他选项吗？如果有，为什么没选？如果没有，约束是什么？"。这比简单说"做错了"更有价值。

### 5️⃣ 制度归因

某些商业行为的问题可能不是"企业道德"的问题，而是"制度缺位"的问题。要把企业责任和制度环境分开讨论，避免把所有问题都归到"企业文化不行"。

> 🔗 与 framework.md 3.4.2 第0步（归因提醒）的 🅲 外部/行业共因概念一致。评分阶段进一步将企业责任与外部因素分开处理。

### 6️⃣ 信息来源
关键数据、事件描述、管理层名言必须标注可信来源（财报、新闻报道、会议记录等）。避免使用百科类二手源作为唯一信源。

### 7️⃣ 自我质疑机制（关键补丁）

**这是最重要的补充规则。** 当遇到有争议的重大事件时，不能只从一个方向分析下结论。在写出最终判断之前，必须完成三轮自问自答。

> 🔗 完整版见 framework.md 2.4节（争议事件自问自答机制）。包含 Q1（反对结论的理由）、Q2（CEO当时有无更好选项）、Q3（企业vs制度责任区分）。这三问是内部思考过程，不在报告中展示原始步骤。

### 8️⃣ 言行一致性
重点关注管理层说的话有没有实现。判断时区分：
- 真心想做成但没做成 → **能力问题**（🅱方向）
- 说了但根本没认真做 → **态度问题**（🅰方向）
- 说了然后做到了 → **信用加分**
- 嘴上说一套实际做另一套 → **重大减分**

> 🔗 评分阶段的能力vs态度区分，详见 framework.md 3.4.2 第0步的 🅰/🅱 归因提醒。

### 9️⃣ 压力测试
重点关注行业困难时期、舆论危机时期的管理层言行。在"公司利益受损"和"兑现价值观"冲突时，管理层选了哪边？这种时候最看人品。

### 🔟 外部校准
对报告中的核心结论，搜索对照第三方权威来源（媒体深度报道、学术研究、分析师报告）进行校准，避免单一信源偏差。
