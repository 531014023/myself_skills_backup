# 实战经验教训

> 从贵州茅台分析实战中总结的关键教训，必须遵守。

---

## 数据获取

### ✅ 正确做法
1. **westock-data 是主数据源**：财报三表数据优先从 westock-data `finance --num 40` 获取，可覆盖约10年年报
2. **mx-data 是子项补充**：资本开支、分红等 westock-data 不提供的子项从 mx-data 获取
3. **股价从 K线API 获取**：`westock-data kline --period year --limit 30 --fq bfq`
4. **产品/地区构成从 mx-data 获取**：主营构成查询

### ❌ 曾经犯过的错误
1. **硬编码数据**：直接把API返回的数字手写到Python脚本里 → 列索引经常搞错，每次API返回格式可能不同
2. **用估算代替真实数据**：2001-2015年财报数据API不可得，就用 `ocf * 1.15` 估算收现 → 数据错误
3. **列索引错误**：`bal[row][17]` 取到了长期借款（lb）而非净资产（te=index 18）→ ROE和净利率全错
4. **字段理解错误**：`CashEquivalents` 是现金及等价物（约500-700亿），不是全部货币资金（约1500-2000亿）
5. **应收科目不全**：只取了应收票据，漏了其他应收款和预付账款
6. **分红用错字段**：用了 `NetFinanceCashFlow`（含借款偿还）而非 `分配股利利润支付的现金`

## 图表生成

### ✅ 正确做法
1. **面积图必须不透明**：`areaStyle: {color: '#91C7AE', opacity: 1.0}`，还要加 `lineStyle: {color: '#91C7AE', width: 2}` 作为轮廓
2. **费用率面积图必须在最底层**：`z: 1`，营收柱状图在 `z: 3`
3. **双坐标系图表要用不同图形区分**：
   - 左轴的用柱状图/线
   - 右轴的用另一种（线/柱），且节点符号要区分
4. **叠加柱状图**：OCF = 自由现金流 + 资本开支，用 `stack: 'ocf'`
5. **地区图表**：国内外用堆叠柱 + 国外占比用独立线的双Y轴

### ❌ 曾经犯过的错误
1. **面积图半透明看不清**：`opacity: 0.6` → 改为 `opacity: 1.0`
2. **地区图表不显示**：国外占比的数据范围与柱状图不匹配，没有配双Y轴
3. **同一坐标系用同一种图形**：现金/有息负债和流动比率都用折线，区分不明显

## 分析文字

### ✅ 正确做法
每个图表配200-400字分析，结构：
1. 关键数据陈述
2. 趋势解读
3. 原因分析
4. 风险/机会判断

### ❌ 曾经犯过的错误
1. 很多图表只有一句话分析或完全没有分析文字
2. 分析太浅，只说"XX很好"而不解释为什么

## 有息负债的特殊处理

- 茅台的 `InterestBearDebt` API值在2023-2025年跳升到123-235亿，这是因为茅台财务公司吸收的存款被API归类为有息负债
- 实际上茅台股份公司本身无银行贷款或债券
- 需要在分析文字中解释这个差异

## 常见Python语法坑

1. 多变量赋值 `a,b,c = [],[],[]` → 如果用分号连写可能出问题，建议分行
2. f-string 中的 `{d["key"]}` 若外层也是 `"` 会冲突，改用临时变量
3. 处理API返回的 `-`（空值）→ `float()` 会报错，需用 try/except

## v2.3 新增教训（美的集团分析，2026-06-06）

### 数据处理
1. **pd.to_numeric 必须用 errors='coerce'**：RAndD等字段早期年份值为'-'，用默认的raise模式会导致 pd.to_numeric 抛出异常，整列保持原始字符串。后续计算如 `rd[i]/rev[i]*100` 会用字符串的原始值（未÷1e8）去除已÷1e8的营收 → 产生如391985206%的离谱数值。

### HTML/JS生成
2. **ECharts CDN 选型**：jsdelivr.net 在中国可能被墙或极慢，改用 `cdnjs.cloudflare.com/ajax/libs/echarts/5.5.0/echarts.min.js`
3. **f-string 嵌入 JS 的变量引用**：`{var_name}` 会被Python求值替换，但若不加 `{}` 就是普通文本。例：`var yrLabels=years.map(...)` → `years` 是文本不是Python变量，JS运行时找不到 → `ReferenceError: years is not defined`。正确：`var yrLabels={years}.map(...)`
4. **颜色对象属性引用**：`itemStyle:{color:R.BLUE}` 在f-string中 `{R.BLUE}` 被当作Python表达式。改用独立变量：`var BLUE='#1976D2'` 然后 `{color:BLUE}`（注意BLUE不带花括号，是JS变量名）

### 图表规范
5. **费用率用堆叠柱状图**：不要用多根独立折线（看不清），改用 stack:'exp' 堆叠柱状图，销售+管理+研发堆叠 = 综合费用率，一目了然
6. **杜邦因子用并排柱状图**：净利率/周转率/乘数用 bar（barGap:'10%'，堆叠式并排），ROE和毛利率保持折线
7. **饼图展示具体科目**：不要按计算分类（生产/经营/投资资产），直接列出资产负债表上的具体科目（货币资金、应收、存货、固定、在建、无形、商誉等），数据更真实可信
8. **FCF 堆叠图加比率折线**：在 OCF=FCF+Capex 堆叠图基础上，右轴增加 FCF/OCF(%) 折线，直观展示自由现金流充裕度变化

### 🔴 HTML 模板生成：禁止使用 f-string（2026-06-06 新增）

9. **🔴 绝对禁止在千行级 f-string 中混写 HTML/JS**：Python f-string 的 `{var}` 求值在千行级字符串中不可靠，`{` 与 `}` 与 JS 对象语法冲突后导致大量未求值变量。2026-06-06 泡泡玛特分析中，gen_html.py 的 f-string 产出了 **38 个未求值变量 + 5 个内联表达式残留 + 全部 `{{}}` 未折叠**，修复耗时远超原始生成。

10. **正确做法：保留字占位 + str.replace() 注入**：
    ```python
    # ✅ 模板用 __VAR__ 占位，完全避开 {} 冲突
    template = '''
    const years = __YEARS__;
    const revenue = __REVENUE__;
    function initChart(id) {
      const c = echarts.init(document.getElementById(id));
    }
    '''
    # ✅ 预计算所有 JS 数据，一次性注入
    html = template.replace('__YEARS__', js_arr(years))
    html = html.replace('__REVENUE__', js_arr(revenue))
    ```
    **关键原则**：数据预计算（Python）→ 保留字占位（模板）→ str.replace 注入（安全），三步分离，永不交叉。

11. **数据注入优先用 JSON**：大量数据对象（如产品堆叠数据、地区构成）直接用 `<script>var data = JSON.parse('__JSON__');</script>` 一次性注入，避免逐个变量替换。

### 🔴 分析文字必须引用实际计算数据（2026-06-06 新增）

12. **🔴 分析文字中的所有数字必须从实际数据集中提取，禁止凭记忆手写**。2026-06-06 泡泡玛特分析中，gen_html.py 的分析文字是手工编写的（如"固定资产周转率飙升至261.8次"），但图表数据是自动计算的（26.2次），导致文字与图表对不上。**原因**：分析文字在 HTML 模板中硬编码，图表数据由 Python 脚本动态计算，两个通道产出的数字不一致。

13. **正确做法**：
    - 所有分析文字通过 Python 的 f-string 或 `format()` 从实际数据中填充数字
    - 示例：`f'应收账款周转率从2019年的{ar2019:.1f}次提升至2025年的{ar2025:.1f}次'`
    - 关键数据（周转率、增长率、占比等）先计算再注入，永不手写
